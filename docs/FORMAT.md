# HPC1 分块格式

这是独立通用包的文件协议，不改动现有 App 格式，不导入任何业务数据库结构。

## 头部：48 字节

| 偏移 | 长度 | 字段 |
| --- | --- | --- |
| 0 | 4 | ASCII `HPC1`，包含格式版本 |
| 4 | 32 | 每文件新生成的随机盐 |
| 36 | 4 | 每块明文最大长度，UInt32 大端，1 至 16777216 |
| 40 | 8 | 明文总长度，UInt64 大端 |

每文件密钥：HKDF-SHA256，输入为调用方的 256 位密钥，salt 为头部随机盐，info 为 UTF-8 `HidePhotoCrypto/HPC1/file-key`，输出 32 字节。不同文件使用独立随机盐，不共享派生密钥。

## 数据块

块数为 `max(1, ceil(明文长度 / 块大小))`。最后一块可以较短，空文件保留一个零明文块。

每块使用 AES-256-GCM combined 编码，增加 28 字节开销：12 字节 nonce、密文、16 字节认证 tag。

- nonce：4 个零字节加 UInt64 大端块索引，从 0 开始。
- AAD：完整 48 字节头部加 UInt64 大端块索引。
- 所有块都使用该文件派生的密钥；同一文件内 nonce 不重复。
- 解密同时验证长度、预期 nonce 和 GCM tag；计算总文件长度时检查整数溢出。

头部变化会使所有块认证失败；对空文件也执行认证。没有满足全部校验的完成输出文件。由于采用临时文件，处理中可能存在尚未完成认证的局部明文；普通失败清理，进程异常终止的残留由调用方清理。

HPC1 是新候选格式，尚无对既有 App 的迁移承诺。更改协议需要新 magic/版本并保留明确的兼容策略。
